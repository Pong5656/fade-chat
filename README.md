# FadeChat — ห้องแชตที่ข้อความจางหายไปเอง

ห้องแชตสดสำหรับคุยพร้อมกันในชั้นเรียนหรือวงสนทนา **ไม่ต้องสมัคร ไม่ต้องล็อกอิน**
ใช้ชื่อเล่นก็เข้าห้องได้ทันที ข้อความในห้องจะ **ค่อย ๆ จางและหายไปเอง** โดย
ยิ่งข้อความสั้นยิ่งหายไว ยิ่งยาวยิ่งอยู่นาน ทุกเครื่องเห็นพร้อมกันแบบเรียลไทม์

---

## หลักการทำงาน

- **ไม่มีเซิร์ฟเวอร์และไม่มีฐานข้อมูลของเรา** ข้อความวิ่งผ่าน MQTT over WebSocket
  ระหว่างเบราว์เซอร์ของผู้ใช้โดยตรง (ค่าเริ่มต้นใช้บรอคเกอร์สาธารณะ `broker.emqx.io`)
- **ทุกคนใช้เวลาเดียวกัน** แต่ละข้อความเก็บเวลาหมดอายุเป็นเวลาสัมบูรณ์ (`expiresAt`)
  ทุกเครื่องจึงเห็นข้อความหายพร้อมกัน ไม่ว่าผู้ใช้จะเข้าห้องช้าหรือหลุดไปแล้วกลับมา
- **ผู้เข้าห้องช้าได้เฉพาะข้อความที่ยังไม่หมดอายุ** เพราะข้อความถูกเผยแพร่แบบ
  *retained* แยกหัวข้อต่อฉบับ (`m/<id>`)
- **ผู้ส่งเป็นผู้ล้างข้อมูลของตนเอง** เมื่อครบอายุ ผู้ส่งจะลบข้อความ retained ของตัวเอง
  ออกจากบรอคเกอร์ เพื่อไม่ให้ข้อมูลค้างอยู่บนเครือข่าย

### อายุของข้อความ

```
อายุ (วินาที) = 6 + 0.35 × จำนวนตัวอักษร   (ต่ำสุด 6 สูงสุด 90)
```

| ข้อความ | จำนวนตัวอักษร | อยู่ประมาณ |
| --- | --- | --- |
| "สวัสดี" | 6 | 8 วินาที |
| "วันนี้ทำการบ้านข้อ 4 ยัง" | 24 | 14 วินาที |
| ข้อความยาว 200 ตัวอักษร | 200 | 76 วินาที |

ข้อความแบบ "ประกาศ" ของเจ้าของห้องอยู่นานกว่าปกติ 60 วินาที

## ฟีเจอร์

**การใช้งานในห้อง**
- เข้าห้องด้วยรหัส 5 ตัวอักษร หรือเปิดจากลิงก์เชิญ / คัดลอกลิงก์ในคลิกเดียว
- พิมพ์แล้วกด `Enter` เพื่อส่ง, `Shift+Enter` ขึ้นบรรทัดใหม่
- เห็นแถบเวลาที่เหลือของแต่ละข้อความ (เจ้าของห้องเห็นเป็นตัวเลขวินาทีด้วย)
- ตัวบอก "กำลังพิมพ์…" ของคนอื่นแบบเรียลไทม์
- ตัวเลขคนออนไลน์และรายชื่อผู้ที่อยู่ในห้อง
- เสียงแจ้งเตือนข้อความใหม่ (เปิด/ปิดได้)
- โหมดไม่เปิดเผยชื่อ (ซ่อนชื่อผู้ส่ง แสดงเป็นรหัสย่อ)
- ปุ่ม "เชื่อมต่อใหม่" และการเชื่อมต่อใหม่ให้อัตโนมัติเมื่อเน็ตสะดุด

**เครื่องมือเจ้าของห้อง**
- ล้างข้อความในหน้าจอของทุกคนพร้อมกัน (ลบข้อมูลบนเครือข่ายด้วย)
- เปิด "ให้เฉพาะเจ้าของห้องส่งได้" (โหมดประกาศ)
- ปิดห้องด้วยตนเอง หรือตั้งเวลาปิดอัตโนมัติ (15/30/60 นาที)

**การควบคุมเนื้อหา**
- ตัวกรองคำไม่พึงประสงค์ พร้อมรายการคำเริ่มต้น และเพิ่ม/ลบคำได้จากหน้าห้อง
- จำกัดความยาวข้อความ 500 ตัวอักษร และหน่วงการส่ง 1.5 วินาทีต่อข้อความ กันสแปม
- ข้อความจากบรอคเกอร์ถูกตรวจด้วยสคีมา (zod) ก่อนนำมาแสดงเสมอ

## ความเสถียรของการเชื่อมต่อ

การเชื่อมต่อ MQTT over WebSocket ถูกออกแบบให้กู้คืนตัวเองได้ โดยไม่ต้องกดรีเฟรช:

- **ไม่มีการทิ้งข้อความช่วงเชื่อมต่อ** ข้อความที่ส่งก่อนเชื่อมต่อเสร็จจะถูกเข้าคิว
  แล้วส่งออกทันทีที่เชื่อมต่อสำเร็จ
- **ตรวจสัญญาณชีพ (watchdog)** หากไม่ได้รับข้อมูลใด ๆ จากบรอคเกอร์เกิน 45 วินาที
  ระบบจะปิดการเชื่อมต่อเดิมและเริ่มใหม่เอง
- **สมัครหัวข้อใหม่ทุกครั้งที่เชื่อมต่อ** เพื่อไม่ให้หลุดการรับข้อความ
  หลังการเชื่อมต่อใหม่หรือเปลี่ยนเครือข่าย
- รหัสลูกข่าย (client id) ผูกกับแท็บผ่าน `sessionStorage` เพื่อไม่ให้ชนกับแท็บอื่น

## วิธีรันในเครื่อง

```bash
npm install
npm run dev          # เปิด http://localhost:3000
# หรือ
npm run build && npm start
```

หน้าแรกคือล็อบบี้สำหรับสร้างห้องหรือเข้าห้องด้วยรหัส

## การตั้งค่าบรอคเกอร์ของตนเอง

ค่าเริ่มต้นใช้บรอคเกอร์สาธารณะซึ่งใช้ร่วมกับคนอื่นและไม่รับประกันความพร้อมใช้
หากใช้กับโรงเรียนหรือวงสนทนาจริงจัง แนะนำให้ใช้บรอคเกอร์ของตนเอง:

```bash
NEXT_PUBLIC_MQTT_URL=wss://your-broker.example.com:8084/mqtt
```

ตัวแปรนี้อ่านตอน build จึงต้องกำหนดก่อน build/Deploy แล้ว build ใหม่
บรอคเกอร์ต้องรองรับ **MQTT over WebSocket** และอนุญาตการเชื่อมต่อแบบไม่ใช้รหัสผ่าน
(ตัวอย่างที่ใช้ได้: EMQX, HiveMQ, Mosquitto ที่เปิด listener `websockets`)

## โครงสร้างไฟล์

```
app/
  layout.tsx              # โครงหลัก ธีม ฟอนต์ Sarabun
  page.tsx                # ล็อบบี้ (สร้างห้อง / เข้าห้อง)
  room/[code]/page.tsx    # หน้าห้องแชต (โหลดแบบไดนามิก)
  not-found.tsx           # หน้าที่ไม่พบ
components/
  chat-room.tsx           # ตรรกะหลักของห้อง (ส่ง/รับ/หมดอายุ/สิทธิ์เจ้าของ)
  message-board.tsx       # กระดานข้อความ พร้อมแถบเวลาถอยหลัง
  lobby.tsx               # ฟอร์มสร้างและเข้าห้อง
  theme-toggle.tsx        # สลับโหมดสว่าง/มืด
lib/
  chat.ts                 # ประเภทข้อมูล สคีมา zod สูตรอายุข้อความ ตัวกรองคำ
  connection.ts           # ฮุกเชื่อมต่อ MQTT over WebSocket
  storage.ts              # เก็บชื่อ/การตั้งค่าใน localStorage ของผู้ใช้
```

## การ Deploy บน Vercel

1. Push โค้ดขึ้น GitHub
2. Import โปรเจกต์บน Vercel (Framework: Next.js, build `npm run build`)
3. (ไม่บังคับ) ตั้ง Environment Variable `NEXT_PUBLIC_MQTT_URL` แล้ว deploy

## ข้อจำกัดที่ควรทราบ

- บรอคเกอร์สาธารณะใช้ร่วมกับผู้อื่น **ไม่ควรใช้กับข้อมูลอ่อนไหว**
- ไม่มีระบบยืนยันตัวตน ผู้ใช้กรอกชื่อเองได้ จึงเหมาะกับวงสนทนาที่เชื่อใจกัน
- ข้อความไม่ถูกเก็บถาวร เมื่อปิดห้องหรือหมดอายุแล้วจะหายไปจากเครือข่าย
- ตัวกรองคำเป็นเครื่องมือช่วยลดปัญหา ไม่ใช่ระบบป้องกันที่สมบูรณ์
